프로젝트 개요

지진 재난 상황에서 로봇이 먼저 실내를 탐색하고 구조 대상을 발견한 뒤 구조 지원으로 연결하는 시스템입니다. 팀 시스템은 TurtleBot4 두 대를 사용해 탐색과 대상 접근·출구 안내 역할을 나누었습니다.

저는 탐색 담당 robot6의 자동 탐색 알고리즘 비교, SLAM·Nav2 실행 환경 구성, 복귀·도킹 시험을 담당했습니다. 세 탐색기의 종료 방식과 주행 기록을 비교하고, 팀원이 사용할 수 있도록 단독 실행 구성을 정리했습니다.

해결하려던 문제

SLAM은 지도를 갱신하지만 다음 탐색 목표를 스스로 정하는 기능과는 구분됩니다. 미지의 공간을 탐색하려면 지도에서 미탐색 경계를 찾고, Nav2가 이동할 목표를 선택하는 탐색기가 필요합니다.

알고리즘의 종료 메시지만으로 전체 공간 탐색 완료나 실제 로봇 정지를 단정하기도 어렵습니다. 후보별로 종료 신호, 정체·반복 목표, 이동 거리, 지도 관측 범위와 실제 정지 여부를 함께 비교했습니다.

담당한 핵심 구현

구간구현·수행 내용설계 목적
SLAM·주행 구성새 SLAM 지도, Nav2, RViz와 로봇 namespace·센서·TF 연결탐색기를 바꿔 비교할 공통 실행 환경 구성
탐색 후보 비교세 기존 Frontier 탐색 패키지를 연결하고 회차별 동작 기록후보의 실행 특성과 운용 적합성 비교
실행 전 점검scan·map·odom·TF 수신, lifecycle active, 도킹·정지 상태 확인입력이 준비되지 않은 상태의 탐색 실행 방지
탐색 결과 분석시작부터 종료·중단까지의 시간, odom 누적 거리, 저장 지도 확인 영역 비교서로 다른 종료 결과를 동일한 성공으로 해석하지 않도록 구분
지도 비교수동 주행 SLAM 지도를 기준으로 회전·이동 정합 후 벽 위치와 관측 범위 비교서로 다른 원점의 지도를 같은 기준으로 분석
실행 환경 공유launch·SLAM·Nav2·탐색 YAML과 실행 순서 정리팀원이 동일 구성으로 단독 시험을 준비할 수 있도록 구성
후속 시험MPPI 설정과 탐색 후 시작 위치 복귀·도킹 흐름 확인탐색 이후 동작 연결 확인

새로운 SLAM이나 Frontier 알고리즘을 처음부터 구현하기보다, 기존 패키지를 로봇 환경에 연결하고 설정·종료 조건·시험 결과를 비교하는 데 집중했습니다.

자동 탐색 구성

LiDAR·Odometry·TF
→ slam_toolbox의 지도 갱신
→ 탐색기의 Frontier 후보·다음 목표 선택
→ Nav2 경로 계획·속도 제어
→ 로봇 이동
→ 지도·odom·종료 상태 기록

단독 explore_lite 실행 구성과 팀 협업 실행은 분리했습니다. 두 구성을 동시에 실행해 Nav2 목표를 중복 전송하지 않도록 실행 단위를 구분했습니다.

알고리즘 비교 결과

새 SLAM 지도와 동일 Nav2 적용 파일을 사용한 최초 비교 회차입니다. 시간은 탐색기 시작부터 자체 종료 보고 또는 중단까지이며, 언도킹·도킹과 시작 위치 재배치는 제외했습니다.

알고리즘관측 시간odom 누적 거리최종 지도 확인 영역종료 결과
explore_lite29.93초6.30m19.62m²자체 종료 보고·실제 정지 확인
frontier_exploration_ros236.60초7.27m19.87m²자체 종료 보고·실제 정지 확인, 막힌 목표 건너뛰기 기록
frontier_toolbox136.15초7.30m19.81m²동일 목표 반복·정체로 감독 중단

각 후보 한 회차의 비교이므로 일반적인 속도·정확도 우열로 확대하지 않았습니다. 지도 확인 영역은 알려진 격자 셀의 면적이며, 전체 실내 공간 대비 탐색률을 뜻하지 않습니다.

단독 시험의 기본 후보로는 explore_lite를 선택했습니다. 지도 일치도가 가장 높아서가 아니라, 자체 종료와 실제 정지 확인, 기존 실행·중단 절차의 재사용성을 우선했습니다. frontier_toolbox는 설정 변경 재시험에서도 정체·예외·중단이 관측되어 운용을 보류했습니다.

문제 해결 과정

문제적용한 해결 방식
SLAM·Nav2·탐색기의 역할이 혼재지도 생성, 경로·속도 계산, 다음 목표 선택을 분리해 실행 구성
알고리즘 종료와 실제 정지가 다름종료 로그와 새 odom·현장 정지 상태를 별도로 확인
같은 목표 반복으로 탐색이 정체반복 목표 설정 변경 재시험, 회차별 종료·중단 사유 기록
Nav2에서 의도한 주행 제어기가 적용되지 않음탐색 전용 YAML의 FollowPath 설정과 실행 중 MPPI 적용 상태 확인
새 SLAM 지도에서도 odom 원점이 유지되어 지도 상태 판단이 어려움도킹 위치에서 새 SLAM을 시작했는지 확인하는 사전 점검 추가
탐색 종료 후 시작 위치 복귀가 연결되지 않음복귀 설정과 취소·새 목표 전송 순서를 점검하고 후속 시험 수행

구현 결과

  • robot6에서 세 탐색기의 동작과 종료 조건을 비교하고 단독 탐색용 후보를 선정했습니다.
  • SLAM·Nav2·탐색기 launch와 설정 파일을 묶어 단독 실행 환경을 공유했습니다.
  • 최초 비교의 DWB 조건과 후속 MPPI 조건을 구분해 기록했습니다.
  • 후속 단독 시험에서 탐색기 종료 보고 → 시작 위치 복귀 → 도킹 상태 확인 흐름을 확인했습니다.
  • 입력 수신 중단 회차는 성공으로 계산하지 않고 중단·취소 결과로 분리했습니다.

후속 14:27 회차에서는 탐색기 종료 보고까지 약 56.5초, 시작 위치 복귀 성공 로그까지 약 38.4초를 기록하고 docked=true·stopped=true를 확인했습니다. 이 결과는 robot6 단독 시험의 관측이며, 팀의 두 로봇 협업 전체 성공률이나 모든 공간 탐색 완료를 의미하지 않습니다.
