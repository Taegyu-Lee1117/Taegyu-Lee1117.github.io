프로젝트 개요

간호사가 약품을 요청하면 조제실의 로봇팔과 컨베이어가 약품을 준비하고, AMR이 병상까지 운반하는 병원 물류 자동화 시스템입니다. Isaac Sim 환경에서 조제·적재·주행·환자 확인·인계·도크 복귀를 연결했습니다.

저는 navigation을 주 담당하고 simulation 구성을 보조했습니다. Ridgeback UR5의 베이스와 센서를 ROS 2·Nav2에 연결하는 단독 주행 구성을 만들고, 팀 주행 모듈의 리셋 이후 costmap 초기화와 관련 테스트를 추가했습니다.

해결하려던 문제

시뮬레이터에 로봇을 배치하는 것만으로 자율주행이 동작하지는 않습니다. Nav2의 속도 명령을 베이스 움직임으로 변환하고, 센서·odometry·TF·지도가 같은 기준으로 연결되어야 합니다.

Ridgeback은 전후·좌우·회전이 가능한 전방향 베이스입니다. 로봇 기준의 속도 명령과 시뮬레이터 베이스 관절의 좌표 관계를 맞추고, Nav2가 해당 이동 특성을 사용할 수 있도록 구성해야 했습니다.

반복 시뮬레이션에서는 로봇 위치를 리셋한 뒤 기존 장애물 정보가 costmap에 남는 문제에도 대응해야 했습니다. 초기 위치와 costmap 초기화를 연결하면서 서비스 응답 대기가 주행 모듈의 상태 발행을 막지 않도록 설계했습니다.

담당한 핵심 구현

구간구현 내용설계 목적
베이스 제어 연동cmd_vel의 linear.x·linear.y·angular.z를 X/Y/yaw 가상 관절 제어에 연결전후·좌우·회전 명령을 시뮬레이터 움직임으로 전달
위치·좌표 연결Odometry와 odom → base_link, base_link → lidar_link TF 구성위치와 LiDAR 관측을 동일 좌표 체계로 연결
LiDAR 연동RTX 2D LiDAR의 scan을 ROS 2로 발행Nav2 장애물 관측 입력 구성
단독 Nav2 구성지도·AMCL·Planner·Controller·RViz와 전방향 DWB 설정 연결초기 위치 지정과 Nav2 Goal 주행 확인
팀 주행 모듈 개선RESET_DONE 이후 initialpose 발행과 global/local costmap 초기화 연결리셋 이후 주행 상태 초기화
비동기 예외 처리costmap clear 서비스 탐색·응답을 제한 시간 내 비동기로 확인응답 지연이 주기적 상태 처리를 막지 않도록 구성

단독 주행 실습에서는 다음 TF 구조를 사용했습니다.

map
→ odom
→ base_link
→ lidar_link

팀 통합에서는 기존 GoToZone·fleet 인터페이스를 유지하면서 리셋 처리를 확장했습니다. 단독 실습의 AMCL 구성과 팀 배송 실행의 위치 기준은 별도 실행 구성으로 다뤘습니다.

리셋 이후 상태 초기화

RESET_DONE 수신
→ 새로운 epoch인지 확인
→ 초기 위치 발행
→ global/local costmap clear 비동기 요청
→ 응답·제한 시간 확인
→ 다음 주행을 위한 상태 처리

동일한 epoch의 리셋 이벤트를 다시 받아도 costmap clear를 반복하지 않도록 기존 이벤트 구분을 유지했습니다.

서비스 응답은 wall clock 기준 시한 안에서 확인하고, 서비스가 없거나 응답하지 않으면 경고를 남기도록 구성했습니다. 서비스 대기 중에도 주기적인 정지 상태 발행이 계속되도록 비동기 처리를 사용했습니다.

문제 해결 과정

문제적용한 해결 방식
시뮬레이터와 ROS 2의 좌표·속도 기준이 다름베이스 명령과 관절·odom·TF 관계를 맞추고 X/Y/yaw 이동을 나누어 확인
LiDAR·TF·지도 연결이 불완전하면 Nav2가 동작하지 않음scan·odom·TF와 lifecycle 상태를 단계별로 점검
USD를 Reference로 추가하면 필요한 Action Graph가 실행되지 않을 수 있음주행용 Stage를 직접 열고 Graph와 Timeline 실행 상태를 확인하는 절차 정리
Isaac Sim과 시스템 ROS 2의 Python 환경이 다름Isaac 실행 환경과 ROS 2 실행 터미널을 분리
위치 리셋 뒤 costmap에 이전 정보가 남을 수 있음initialpose 이후 global/local costmap clear 요청 추가
느리거나 없는 서비스가 상태 처리를 막을 가능성비동기 호출·제한 시간·경고 처리와 서비스 대역 테스트 구성

구현 결과

  • Isaac Sim에서 X/Y 이동과 yaw 회전, 전방향 베이스 제어를 확인했습니다.
  • scan·odom·TF·cmd_vel·clock을 연결하고 RViz Nav2 Goal 주행을 확인했습니다.
  • 팀 navigation 모듈에 리셋 이후 costmap 초기화를 추가했습니다.
  • 서비스 대역으로 두 costmap 호출, 동일 epoch 중복 처리, 느린 응답 중 상태 발행과 서비스 부재를 확인하는 테스트를 구성했습니다.
  • 로봇 모델·센서·좌표계·주행 소프트웨어를 연결하고, 반복 실행 과정의 상태 초기화까지 담당했습니다.

주행 결과는 Isaac Sim 환경의 결과입니다.
