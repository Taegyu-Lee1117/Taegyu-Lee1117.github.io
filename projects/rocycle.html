YOLO 학습·평가 · ROS 2 연동 · UI·DB 연결

프로젝트 개요

고정 카메라로 컨베이어 위 재활용품을 인식하고 M0609 로봇팔로 분류하는 시스템입니다. 팀 시스템은 객체 인식, 좌표 변환·추적, 파지·분류, 음성 상호작용, 관제 화면과 처리 기록으로 구성했습니다.

저는 YOLO 객체 인식 모델의 학습·평가, ROS 2 인식 연동, UI·DB 연결을 담당했습니다. 이미지에서 검출된 클래스와 위치를 후속 노드가 사용할 수 있도록 전달하고, 로봇의 처리 결과를 웹 API와 데이터베이스로 연결했습니다.

항목내용
로봇·장비Doosan M0609, OnRobot RG2, C270 웹캠, 컨베이어
개발 환경Ubuntu 24.04, ROS 2 Jazzy, Python
인식 기술YOLO12s, Ultralytics, OpenCV, PyTorch
연동 기술ROS 2 Topic, Docker, NVIDIA GPU, FastAPI, PostgreSQL
담당 범위모델 학습·평가, 인식 노드와 실행 환경 구성, 처리 결과 브리지

해결하려던 문제

객체 인식 모델의 결과를 로봇이 곧바로 사용할 수 있는 것은 아닙니다. 검출된 클래스, 픽셀 위치, 신뢰도를 후속 노드에 전달하고, 카메라 좌표를 로봇 기준 좌표로 변환하는 흐름을 연결해야 합니다.

또한 학습 환경에서의 모델 성능과 실제 카메라 영상의 동작은 따로 확인해야 합니다. GPU 추론 환경을 분리하면서도 Host의 ROS 2 영상과 검출 결과가 정상적으로 오가도록 구성했습니다.

로봇 처리 상태는 반복해서 발행되므로, 동일한 완료 이벤트가 데이터베이스에 반복 저장되지 않도록 식별과 전송 처리가 필요했습니다.

담당한 핵심 구현

구간구현 내용설계 목적
데이터 점검학습·검증·시험 분할의 클래스, 라벨 누락·오류, 분할 간 동일 이미지 중복 검사학습 입력과 평가 데이터 구성 확인
모델 학습·평가6개 클래스에 대해 YOLO12s 학습, Precision·Recall·mAP와 혼동행렬 확인인식 성능을 여러 지표로 평가
ROS 2 인식 노드/image_raw 구독, OpenCV 영상 변환, YOLO 추론, 검출 데이터와 결과 영상 발행카메라 입력과 후속 로봇 처리 연결
검출 결과 전달클래스·confidence·bbox·중심 픽셀을 ROS 2 Topic으로 전달tracking_node가 좌표 변환 입력으로 활용
GPU 실행 환경Host 카메라와 Docker 추론 분리, 모델 경로·device 파라미터화Host·컨테이너에서 동일 노드 재사용
처리 결과 브리지/ui/state의 완료 결과를 /api/processing 요청으로 변환로봇 처리와 UI·DB 기록 연결

최종 모델은 건전지, 캔, 종이상자, 라벨 있는 PET, 플라스틱, 비닐의 6개 클래스를 구분하도록 구성했습니다.

카메라 픽셀 좌표를 로봇 좌표로 직접 간주하지 않고, 기존 tracking_node의 변환 경로에 연결했습니다. 검출 데이터 발행과 로봇의 실제 파지 판단을 분리했습니다.

인식·데이터 연결 흐름

C270 웹캠
→ Host의 /image_raw 발행
→ Docker GPU YOLO 추론
→ 클래스·bbox·중심 픽셀 발행
→ Host tracking_node
→ Robot Base 좌표 출력
→ 로봇 파지·분류 처리

로봇 처리 결과는 별도 브리지를 통해 저장하도록 구성했습니다.

로봇 /ui/state
→ 완료된 처리 결과 추출
→ 클래스명 정규화·이벤트 식별
→ 전송 대기열
→ FastAPI /api/processing
→ PostgreSQL
→ 관제 화면·처리 이력

진행 중 상태는 저장 대상에서 제외하고, 확인 필요 통으로 보낸 결과는 review_pending으로 구분했습니다. 전송 대기·완료 ID를 관리해 같은 이벤트의 반복 전송을 억제하고, API 요청 실패 시 대기열의 항목을 다음 전송 주기에 다시 시도하도록 구성했습니다.

문제 해결 과정

문제적용한 해결 방식
기존 RealSense Depth 코드가 C270 RGB 입력과 맞지 않음C270 영상만으로 실행되는 인식 노드를 분리
동일 이름의 ROS 2 패키지가 충돌독립 object_detection 패키지와 단일 워크스페이스로 실행 경로 정리
Host와 Docker에서 모델 경로·추론 장치가 다름model_path·device 파라미터와 모델 마운트 경로 사용
컨테이너에서 ROS 2 영상을 받지 못할 가능성Host 네트워크와 Domain ID·RMW·DDS 설정을 맞춰 실제 Topic 수신 확인
검출 클래스와 DB 클래스의 이름이 다름클래스 별칭을 정규화하고 지원하지 않는 클래스는 저장에서 제외
반복 발행되는 상태가 중복 처리 이력으로 이어짐완료 결과만 추출하고 이벤트 ID를 기준으로 전송 대기·완료 상태 관리

구현 결과

최종 모델은 이미지 크기 640, 50 epochs, batch 8 조건으로 학습했습니다. 데이터셋은 Train 1,500장, Validation 427장, Test 213장으로 구성했습니다.

내부 Test 지표결과

Recall1.0000
mAP@0.50.9950
mAP@0.5:0.950.9691

conf=0.25의 내부 Test 혼동행렬에서는 213개 객체가 모두 정답 클래스에 검출되었습니다. 위 수치는 내부 데이터셋 평가 결과이며, 실제 컨베이어의 파지 성공률을 의미하지 않습니다.

  • C270 영상의 ROS 2 입력과 Bounding Box 결과 영상 출력을 확인했습니다.
  • Docker의 GPU 추론 결과가 Host의 tracking_node로 전달되고 Robot Base 좌표가 출력되는 흐름을 연결했습니다.
  • 처리 완료·확인 필요 상태를 분리해 저장하는 UI·DB 브리지를 구현했습니다.
  • 모델 성능 평가부터 로봇 소프트웨어와의 데이터 연동까지 담당했습니다.
